# M1 – Config-Flow, Optionen, Verbindungen, Tool-Registry (24.11.2026)

Ausgeführt nur lokal: Unit-/HA-Tests mit Fake-IMAP/SMTP, Ende-zu-Ende gegen ein frisches HA 2026.11.3 ohne Mailserver. Kein GMX-Konto, keine produktive Instanz.

## Gebaut

| Datei | Inhalt |
|---|---|
| `config_flow.py` | **user:** E-Mail, App-Passwort, erlaubter Benutzer (aktiv, nicht system-generiert, D9), Server-Section (eingeklappt, GMX-Voreinstellung). Prüft IMAP-Login + CAPABILITY + LIST und SMTP-Login im Executor; `unique_id` = Adresse (klein). **reauth:** neues App-Passwort. **reconfigure:** erlaubter Benutzer und Server. **options:** Verbindungs-URL + `claude mcp add`-Vorlage (Platzhalter statt Token, D22), Tool-Schalter (D12, D23). |
| `__init__.py` | Setup meldet sich einmal an: Auth-Fehler → Repair-Hinweis `imap_possibly_disabled` + Reauth; TLS-/Verbindungsfehler → erneuter Versuch. Spätere Auth-Fehler (z. B. GMX schaltet IMAP ab) → Hinweis + Reauth. Timer schließt ruhende Verbindung (`IDLE_CHECK_INTERVAL_S`). Entladen meldet ab. |
| `connection.py` | Einstellungen aus Entry-Daten, TLS-Kontext (certifi, TLS ≥ 1.2), Repair-Hinweis. |
| `connect_info.py` | URL: explizite externe URL → Nabu Casa → interne URL → Platzhalter. |
| `mcp/registry.py` | Statischer Katalog (`TOOL_SPECS`: Name + Stufe), Bau je Entry, Filter nach Schaltern – je Nachricht ausgewertet, also ohne Reload wirksam. |
| `mcp/tools/status.py` | `gmx_get_status` (R): Verbindung, Anzahl Ordner, erkannte Spezialordner, `APPENDLIMIT`, fehlende Capabilities. Keine Adressen, keine Inhalte. Fehler als Code (`auth_failed_or_imap_disabled`, `tls_error`, …). |
| `mcp/protocol.py` | Tool trägt Stufe (Annotationen daraus), Zeitlimit je Aufruf (120 s). |
| Übersetzungen | de/en für Flow, Fehler, Abbrüche, Optionen, Schalter-Beschriftungen, Repair-Hinweis, Exceptions. |

## Prüfungen

- **437 Tests grün:** `tests/client` 313, `tests/mcp` 54 (u. a. SPEC §7: jedes Tool ausgeschaltet weder gelistet noch aufrufbar; jedes Tool hat de/en-Beschriftung), `tests/ha` 70 (Flow inkl. aller Fehlerarten, Duplikat, mehrere Konten, Reauth, Reconfigure; Lebenszyklus; Options-Flow; Schalter wirken über HTTP sofort und ohne Reload). Probe-Tests separat (`-p no:homeassistant`). `ruff`, `mypy --strict` sauber.
- **Gegenprobe der Tests:** sechs absichtlich eingebaute Fehler (Schalter-Filter wirkungslos, kein Reauth zur Laufzeit, kein Repair-Hinweis, leere Auswahl → Voreinstellung, keine SMTP-Prüfung, kein Logout beim Entladen) – jeder wurde von mindestens einem Test erkannt.
- **Ende-zu-Ende, HA 2026.11.3:** Formular des Config-Flows wird korrekt serialisiert (Selektoren, eingeklappte Section); Absenden mit unerreichbarem Server → `cannot_connect`; fremde Benutzer-ID → 400 durch den Selektor. Entry ohne Mailserver → `setup_retry` mit übersetztem Grund, Endpunkt 404. Options-Flow zeigt `https://<externe URL>/api/gmx_mail_mcp/<id>/mcp` und die Claude-Code-Vorlage; Speichern einer leeren Auswahl bleibt leer. Testpasswort nie im Log.

## Nicht geprüft / offen

1. **Echter Mailserver im Ende-zu-Ende-Test** fehlt (kein Docker-Daemon hier). Die Servertests der CI (GreenMail, Dovecot) prüfen die Client-Schicht, nicht den Flow. Live-Test gegen GMX nur durch dich.
2. **claude.ai-Anmeldung über HA (D22)** weiter nicht live geprüft.
3. Entries aus dem M0-Spike (nur `allowed_user`) werden nicht migriert; der Spike wurde nie veröffentlicht.
4. Optionen der Vorlage (`options.py`: Versand, Limits, Ordner) sind noch nicht im Options-Flow (D23); `permissions` ist durch `enabled_tools` abgelöst und wird mit M3–M5 aufgeräumt.
