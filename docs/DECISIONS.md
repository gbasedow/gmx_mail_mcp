# DECISIONS.md – Entscheidungen

| Nr. | Datum | Entscheidung | Begründung |
|---|---|---|---|
| D1 | 2026-11-23 | Client-Code aus `gbasedow/gmx_mail` wird **kopiert**; dieses Repo ist eigenständig. | Wahl des Nutzers. Kein gemeinsames Paket, kein Umbau der Vorlage. Folge: Fehlerkorrekturen müssen bei Bedarf in beiden Repos erfolgen. |
| D2 | 2026-11-23 | Der MCP-Server läuft als **eigene HA-Integration** mit HTTP-Endpunkt (`HomeAssistantView`, `requires_auth`). | Wahl des Nutzers. HA prüft Bearer-Tokens (auch Long-Lived) selbst; kein zusätzlicher Prozess. |
| D3 | 2026-11-23 | Schutzmechanismen der Vorlage werden übernommen (Allowlist, Vorschau + Code, Limits, Papierkorb zuerst) und **zusätzlich** je Tool schaltbar. Voreinstellung: nur lesende Tools an. | Wahl des Nutzers. Der Tool-Schalter allein begrenzt nicht, wohin ein eingeschaltetes Sende-Tool schreibt. |
| D4 | 2026-11-23 | Zugriff von außen über Nabu Casa mit claude.ai/App als Ziel-Client. | Wahl des Nutzers. Risiko Bearer-Token vs. OAuth, siehe SPEC §2 und OFFENE-PUNKTE Nr. 4; Spike M0 klärt das vor jeder weiteren Arbeit. |
| D5 | 2026-11-23 | Übernommen wurde nur die HA-freie Schicht (`client/`, `const.py`, `options.py`, `envelope.py`, `confirm.py`) samt 313 Tests; HA-gebundene Module (Aktionen, Coordinator, Flows) nicht. | Sie hängen an `hass.services` und müssen für MCP neu geschrieben werden. Importpfade auf `custom_components.gmx_mail_mcp` umgestellt, Tests laufen unter Python 3.14 ohne HA-Plugin. |
| D6 | 2026-11-23 | Übernommene Entscheidungen der Vorlage gelten weiter, außer „kein eigener MCP-Server“ (Vorlage Nr. 1) und die ha-mcp-Freigabe (Nr. 9): Nr. 3, 6, 10, 19–24, 36, 40 (Details in `gbasedow/gmx_mail`, `docs/DECISIONS.md`). | Gleiche GMX-Eigenheiten, gleiche Sicherheitsüberlegungen. |
| D7 | 2026-11-23 | `gmx_mail` wird nach erfolgreichem Betrieb von `gmx_mail_mcp` **abgelöst**. Bis dahin ist nur eine der beiden Integrationen je Konto aktiv. | Aussage des Nutzers: GMX Mail wird nicht mehr gebraucht. Beide gleichzeitig würden IDLE-Verbindungen und das GMX-Verbindungslimit teilen. |
| D8 | 2026-11-23 | Autorisierung wie beim eingebetteten ha-mcp: Long-Lived Access Token von Home Assistant genügt (Bearer). Kein eigenes OAuth. Spike M0 prüft den Weg Nabu Casa → claude.ai vor weiterer Arbeit. | Vorgabe des Nutzers; ha-mcp läuft bei ihm auf diese Weise. Ob der claude.ai-Connector genau diesen Header-Weg trägt, ist nicht von mir verifiziert, deshalb der Spike. |
| D9 | 2026-11-23 | Zugriff nur für **einen eigenen HA-Benutzer**: Der Nutzer erzeugt die Tokens unter diesem Benutzer. Der Endpunkt lehnt Tokens anderer Benutzer ab (Option „erlaubter Benutzer“, wird im Config-Flow gewählt). | Vorgabe des Nutzers. Zweite Sperre neben dem Token; ein Token eines anderen Benutzers öffnet den Server nicht. |
| D10 | 2026-11-23 | Anhänge sind **als Text und als Datei** abrufbar: `get_attachment` mit Parameter `mode` = `text` / `file` / `both`. Textextraktion für PDF, DOCX, XLSX und reine Textformate; die Datei kommt als MCP-Inhalt (Bild/Blob). | Vorgabe des Nutzers. Offen bleiben Größenlimit, Teilabruf und die Auswahl reiner Python-Bibliotheken für die Extraktion (Kompatibilität mit HA, kein kompiliertes Paket). |
| D11 | 2026-11-23 | **Mehrere GMX-Konten** werden unterstützt: ein Config-Entry und ein Endpunkt je Konto (`/api/gmx_mail_mcp/<entry_id>/mcp`). | Wunsch des Nutzers. |
| D12 | 2026-11-23 | Tool-Schalter nur im **Konfigurationsfluss** (Options-Flow), nicht als HA-Entitäten. Voreinstellung: nur lesende Tools (Stufe R) an. | Vorgabe des Nutzers. Als Entitäten könnte ein LLM mit ha-mcp-Zugriff sich Tools selbst freischalten. |
| D13 | 2026-11-23 | Umfang: Postfach **vollumfänglich verwalten**. Zusätzlich zu den 21 Aktionen der Vorlage: Roh-Mail (.eml), Threads, Ordner abonnieren, `.eml` hochladen, Capabilities, Keywords. Mailbox-weites `EXPUNGE` bleibt ausgeschlossen (nur `UID EXPUNGE`). | Vorgabe des Nutzers; der Ausschluss ist eine Sicherheitsgrenze aus der Vorlage und ändert nichts an der Verwaltbarkeit. |
| D14 | 2026-11-23 | Größenlimit für Anhänge **konfigurierbar**, Voreinstellung **10 MB**. | Vorgabe des Nutzers. |
| D15 | 2026-11-23 | Keine Sensoren und keine Ereignisse in der ersten Version; damit keine dauerhafte IDLE-Verbindung. | Nutzer braucht sie nicht. Spart eine der höchstens zwei GMX-Verbindungen und vermeidet Dauerlast; kann später als Option nachgerüstet werden. |
| D16 | 2026-11-23 | Python 3.14 wird vorausgesetzt (HA 2026.11). Die Version der echten Instanz wird vor M1 am laufenden Container bzw. in den Systeminformationen bestätigt. | Aussage des Nutzers; die Vorlage nennt ≥ 3.14.2 aus Recherche, ungeprüft. |
