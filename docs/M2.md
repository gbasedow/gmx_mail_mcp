# M2 – Lese-Tools und Anhänge (24.11.2026)

Version 0.0.4. Ausgeführt nur lokal (Tests mit Fake-IMAP, echtes HA 2026.11.3 ohne Mailserver). Kein GMX-Konto, keine produktive Instanz.

## Entscheidungen vor dem Bau

D26 (Datei bis zum Options-Limit, keine kleinere Standardgrenze), D27 (pypdf + Standardbibliothek), D28 (Roh-Mail, Thread, Schlagwörter, Capabilities in M2), D29 (HTML nur mit Option), D30 (MCP-Protokoll bleibt bei 2025-11-25). Grundlage: Recherche zu MCP `2026-07-28` (großer Umbruch, später) und zu den Größenlimits der Claude-Clients (claude.ai ≈ 150 000 Zeichen je Tool-Ergebnis).

## Tools (alle Stufe R, Voreinstellung an)

| Tool | Inhalt |
|---|---|
| `gmx_get_status` | wie M1, zusätzlich alle IMAP-Capabilities |
| `gmx_list_folders` | Ordner mit Pfad, Rolle, optional Zählern |
| `gmx_search` | Felder wie in der Vorlage (from/to/cc/subject/text/body, Datum, Flags, Größe, Keyword, UID-Bereich), Sortierung, Seiten mit `next_cursor` (an Kriterien gebunden), Rückfall für frische Mails (GMX-Index ≈ 30 s) |
| `gmx_get_message` | Kopfzeilen, bereinigter Text in Zufallsrahmen, Flags, Anhangsliste, Seiten über `offset`; `format` text / html_as_text / html (nur mit Option, D29) / raw_headers |
| `gmx_get_attachment` | `mode` text (Standard) / file / both. Typ nach Inhalt (nicht nach Angabe oder Dateiname); Bilder als MCP-Bild, sonst eingebettete Ressource; Text aus PDF, DOCX, XLSX, Textformaten, bereinigt und gerahmt, seitenweise; SHA-256, Größe, Warnung `type_mismatch` |
| `gmx_get_raw_message` | ganze Mail (.eml) als eingebettete Ressource, Größe wird **vor** dem Herunterladen geprüft |
| `gmx_get_thread` | Gesprächsverlauf im selben Ordner (GMX: ORDEREDSUBJECT, Warnung `grouped_by_subject`) |
| `gmx_list_keywords` | Schlagwörter aus der FLAGS-Antwort des Ordners, `custom_keywords_allowed` |

Gemeinsam: strenge Argumentprüfung (unbekannte Felder, Typen, Bereiche, Muster → `isError` mit `invalid_arguments`), Fehlercodes statt Texte aus dem Server (`folder_not_found`, `uidvalidity_changed`, `message_not_found`, `too_large`, …), Envelope mit `account` (Titel des Eintrags, D11), `content_trust`, Budget 24 KB für den Textteil. Nur EXAMINE und `BODY.PEEK`, nie `\Seen`, nie CLOSE.

## Optionen (Konfigurieren)

Neu: „Größenlimit für Anhänge und .eml“ (1–10 MB, Standard 10, D14) und „HTML-Ausgabe erlauben“ (Standard aus, D29). Beides wirkt sofort.

## Schutz bei der Extraktion (`extract.py`)

PDF: pypdf, höchstens 500 Seiten, 2 Mio. Zeichen, verschlüsselt → `pdf_encrypted` (leeres Passwort wird versucht), Seiten ohne Text → `no_text_found`. DOCX/XLSX: ZIP ≤ 5 000 Einträge, je XML ≤ 30 MB, zusammen ≤ 100 MB, Kompressionsverhältnis ≤ 200, kein DOCTYPE/ENTITY (keine Entity-Tricks), XLSX ≤ 500 000 Zellen. Jeder Parserfehler → `extraction_failed`. Läuft im Executor, nicht in der Event-Loop.
